# Report From Export

**Live:** https://report-from-export.vercel.app

Paste the CSV your system already exports (work orders, POS sales, timecards, a job board) and ask what you want to know. Get the owner's report: a headline, the findings to act on, and the tables behind them.

## Where it came from

Job postings are a business writing down, in its own words, a step of work it will pay a
salary for. A sweep of Twin Cities postings from the last 30 days (Craigslist jobs plus
public Greenhouse, Lever and Ashby boards, 2026-10-17; `~/Desktop/hiring-signals`) found
**25 distinct employers** posting a version of this one:

> Prepare financial and management reports for the owner  
> Prepare sales reports and metrics for Sales Manager review  
> compile operational information and metrics  
> Translate data into clear, actionable recommendations for dealership leadership  

The page opens on that line, then shows the step already done on a worked example.

## What's free, what's paid

| free (no login) | paid ($5, once) |
|---|---|
| the report on the first 200 rows of any export | **every row of every export, every run, with the tables to download** |

Below the paywall, a quieter line: *want this built around your team's actual workflow?*
That is custom work, negotiated, with no price on the page. Clicks are tracked as `custom_click`.

## Price

**$5, once.** Set by Aidan on 2026-10-17 as a hypothesis under test, not a fact. One run
saves roughly an hour of an office person's time, so a tenth of one use would be higher;
$5 tests whether price is what stops a small business from buying at all (msp-house-index
drew 10 checkouts and 0 payments at $100). Revise on the funnel: `preview_open`, `run`,
`run_ok`, `paywall_click`, `checkout_open`, `paid`, `unlock`, `custom_click`.

## How it works

Two Claude Opus 5.5 calls around code. The first reads only the column names and a sample and plans the metrics that answer the question. Code computes every metric over every row. The second writes findings from the computed values only, and code drops any sentence that states a number the computation did not produce.

| route | does |
|---|---|
| `POST /api/run` | the tool. Free runs cap the items; a password in `x-password` lifts the cap |
| `POST /api/checkout` | Stripe embedded Checkout, $5; mints the password (nonce + HMAC under `ACCESS_SECRET`) into session metadata and the invoice footer |
| `GET /api/session-status` | the return page: once paid, shows the password |
| `POST /api/stripe-webhook` | via the shared `stripe-router` (no endpoint of its own): emails the password once |
| `POST /api/check` | does this password unlock? |

`site/index.html` and `site/for/*` are generated by `scripts/build_page.py` from
`tool.json` and `render.js`; never hand-edit them. Local: `node scripts/serve.js`
(needs `ANTHROPIC_API_KEY`). Deploy: `python3 scripts/deploy.py` with the keys from
`bricks/.env`. What you paste is sent to the model to do the work and is not stored.

`DATA_MODEL.md` is the ideal model, written before the build, and the field-by-field
check against reality. The example on the page is synthetic.
